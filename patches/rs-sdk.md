# Changes and workarounds for vendored rs-sdk

rs-sdk is a git submodule at `vendor/rs-sdk`, pinned by its gitlink in the parent repo and by `rs-sdk.pin`. `bun run check-pin` checks the checkout against the pin. We do not edit files under `vendor/` from package code. Each item below says how we deal with an rs-sdk behavior.

Setup for a fresh clone: `git clone --recurse-submodules <repo>`, then in `vendor/rs-sdk` run `git config core.autocrlf false` and `git config core.eol lf` before any checkout. rs-sdk marks its files `text=auto`, so without `core.eol lf` a Windows checkout still gets CRLF, and the engine content pack then fails (`Invalid property value: param=damagetype,^slash_style`). Item 1 depends on this. A fresh checkout has no `server/engine/data/players`; create it before a practice preset, or `sdk/test/utils/save-generator.ts` writes saves to `vendor/rs-sdk/engine/data/players`, where the engine does not read them.

1. **LF line endings are required.** `bots/create-bot.ts --local` replaces `SERVER=localhost\n`. With CRLF checkouts (`core.autocrlf=true`, the Windows default) the match fails, and the bot env keeps `SERVER=localhost` with no `GATEWAY_URL`. Fix: `scripts/clone-vendor.sh` clones with `-c core.autocrlf=false`. Upstream: MaxBittker/rs-sdk#130 makes `create-bot.ts` accept CRLF. When the pin includes it, a clone needs `core.eol lf` only for the content pack.
2. **Telemetry is on by default.** `bot.env` from the template has `TELEMETRY=true`, and `sdk/bug-report.ts` posts to `https://rs-sdk-demo.fly.dev/bug-report`. Our `createBot` rewrites it to `TELEMETRY=false`.
3. **Cheats are off locally.** `server/engine/src/server/login/LoginThread.ts:60` sets `staffmodlevel = 0`. Not patched. Practice presets use `sdk/test/utils/save-generator.ts` instead.
4. **The lite client mishandles locs on bridged tiles.** On a tile whose level-1 map flag has LinkBelow, `server/webclient/src/lite/protocol/zone.ts` keys a loc change by the player's level, but `lite/world/CollisionBuilder.ts` reads the raw level (one up) there, so an opened door stays shut in the routing map; and `lite/world/SceneLite.ts` answers `nearbyLocs` from the raw level under the bridge. The browser client handles both (`client/Client.ts` `locChangeUnchecked`, `World.setBridge`). Workaround: `packages/core/src/bridgefix.ts` `fixBridgedLocChanges(session.client)` wraps SceneLite at runtime (no vendor edit). Opt-in per script; used by `scripts/generated/quest-seaslug.ts` (fishing platform doors). Evidence:(`research/quest-plan.md` 1n). Upstream: reported as MaxBittker/rs-sdk#129.
5. **Install packet observers before the lite session pumps.** Local patch: `server/webclient/src/lite/session.ts` accepts an optional `onClient` callback after construction and before the first packet pump. It closes the connection if that callback throws. The two observer hunks are stored in [rs-sdk-session-observer.patch](rs-sdk-session-observer.patch), against the pinned file; other local vendor changes are excluded. `packages/core/src/inprocess.ts` installs its shim there, so the first full equipment packet cannot arrive before its observer. Account ownership is recorded after the session starts successfully. A missing full packet remains unknown; partial packets, a retained component or another client's inventory cannot establish readiness. The pin is unchanged. Packet-order tests and the native quest/smelting/supply evidence are retained under `.practice/travel-native-20261027/`.

6. **Working-tree vendor changes.** `patches/rs-sdk-working.patch` holds every local change under `vendor/rs-sdk` that the pin does not carry (pack config and interface tools, the lite session observer, `session-end.test.ts`, the action trace of item 8, the lockstep engine of item 10). A fresh clone applies it with `git -C vendor/rs-sdk apply ../../patches/rs-sdk-working.patch`. The pack tools keep `BUILD_VERIFY` on and check fixed fork CRCs; upstream turns the check off (`server/Dockerfile:57`). When an upstream content change alters a packed archive, set its CRC from the newly packed file (`Packet.getcrc` over `data/pack/client/<archive>`) in this patch. Upstream: MaxBittker/rs-sdk#131 holds the logout drain (`pumpSessionEnd` and `session-end.test.ts`). When the pin includes it, remove those hunks from the patch.

7. **A re-login takes over the Player still in the world.** A client that dies without logout leaves its Player in the world for `TIMEOUT_NO_CONNECTION` (500 ticks, `server/engine/src/engine/World.ts:150`). At the pin, a login for that account attaches the new client to that Player (`World.ts` `processLogins`, `Player.onTakeover`): no save is reloaded, `[login,_]` does not run, and a death, delay or combat lock carries on. The old client gets LOGOUT. A login while the old Player waits in `logoutRequests` is still refused with 5. Practice proof and the live-server status: `research/community-and-upstream.md` 8.6. Admission uses it only for a server in `packages/core/src/session-takeover.ts` `TAKEOVER_SERVERS`.

8. **Action trace for the coverage scoreboard.** Local patch: `server/engine/src/engine/script/ScriptRunner.ts` `init` is the one place every content script starts. If `ACTION_TRACE_FILE` is set and `NODE_PRODUCTION` is off, it appends the script name, such as `[oploc1,_door]`, on the first run of each script in that engine process. `packages/practice/src/stack.ts` sets the flag to `.practice/action-trace.log`. The live server does not run this patch. `packages/router/src/coverage.ts` joins the trace with `knowledge/actions.json` as `totals.actionsFired`. An engine that runs the patch only picks it up at start. A checkout that has the other patches adds this one with `git -C vendor/rs-sdk apply --include=server/engine/src/engine/script/ScriptRunner.ts ../../patches/rs-sdk-working.patch`.

9. **Nearby players carry no prayer, gear or HP.** `server/webclient/src/bot/StateCollector.ts` `collectNearbyPlayers` publishes name, combat level and tile only. The lite client still decodes head icons, worn items and the last hitmark HP into each `ClientPlayer`. Workaround: `packages/core/src/opponent.ts` `readOpponents(session.client)` reads them from the client (no vendor edit). `openStyles` lists the attack styles the opponent does not protect against.

10. **Lockstep practice engine with a seed.** Local patch, adapted from TestingPurposes/rs-stun-toolkit (MIT, `4e40de3d`; license text in `research/stun-toolkit-LICENSE.txt`): `server/engine/src/engine/World.ts` `simAwaitAcks`, `server/engine/src/server/ClientSocket.ts` `lastRecvAt`, and `server/engine/src/simseed.ts`, which `app.ts` imports first. With `SIM_LOCKSTEP=1` the engine has no wall clock: the next tick runs when every connected client has sent bytes after the last tick, or after `SIM_ACK_MS`. `SIM_DET=1` runs no tick while no client is connected and no login or logout is in flight. `SIM_SEED` reseeds `Math.random` and `JavaRandom` at the start of each tick from the seed and the tick count since the login of an account that matches `SIM_SEED_ANCHOR`. `SIM_STAT_FILE` receives one line for each 25 ticks with the mean wait and its cause. `SIM_TRACE_FILE` receives one line for each tick with a hash of every player and npc tile and the random draws of the tick before; two runs with one seed and a fresh engine give the same file. Without `SIM_LOCKSTEP=1` the engine ticks on the wall clock as upstream does. The bot side is `packages/core/src/inprocess.ts`: from the first game tick it holds the client's flush and sends the actions of one tick with a closing `NO_TIMEOUT` in one write. The write waits until the script waits for a tick again (an open tick stream in `packages/core/src/tick-stream.ts`, a wait action, or an SDK state waiter), so work off the tick clock, such as a world-map load, costs no ticks; `SIM_BUSY_MS` (2000) bounds the wait. `packages/practice/src/stack.ts` `lockstep` sets the flags; `scripts/measure/aio-practice-bench.ts` uses it with `BENCH_LOCKSTEP=1`. `Bun.spawn` must receive `env: {...process.env}` for a bot to see a flag set at run time. Gap: a worker that sleeps on the wall clock with no tick wait holds each tick for `SIM_BUSY_MS`; the client counts one frame for each 20 ms loop, so an animation lasts more ticks than on a 400 ms server.
11. **Action trace.** Local patch: with `SIM_ACTION_FILE` set, `server/engine/src/simseed.ts` writes one line for each message from a client (`engine/entity/NetworkPlayer.ts`) and one line for each tick in which a player holds a target (`engine/entity/Player.ts`), with the state that decides if the engine runs the action. `engine/entity/Npc.ts` writes one line for each player an NPC could hunt, with the check that refused or `candidate`. The file is flushed each cycle from `engine/World.ts`. No effect when the variable is not set.
12. **No AFK event with random events off.** Local patch: `engine/script/handlers/PlayerOps.ts` makes `afk_event` false when `NODE_RANDOM_EVENTS` is off. Upstream content scripts return from a skill action when `afk_event` is true, and with random events off no event spawns, so the action was lost with no message. Upstream: MaxBittker/rs-sdk#128 holds this change. When the pin includes it, remove this hunk from the patch.
