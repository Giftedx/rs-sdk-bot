# Changes and workarounds for vendored rs-sdk

rs-sdk is a git submodule at `vendor/rs-sdk`, pinned by its gitlink in the parent repo and by `rs-sdk.pin`. `bun run check-pin` checks the checkout against the pin. We do not edit files under `vendor/` from package code. Each item below says how we deal with an rs-sdk behavior.

Setup for a fresh clone: `git clone --recurse-submodules <repo>`, then in `vendor/rs-sdk` run `git config core.autocrlf false` before any checkout. Item 1 depends on this.

1. **LF line endings are required.** `bots/create-bot.ts --local` replaces `SERVER=localhost\n`. With CRLF checkouts (`core.autocrlf=true`, the Windows default) the match fails, and the bot env keeps `SERVER=localhost` with no `GATEWAY_URL`. Fix: `scripts/clone-vendor.sh` clones with `-c core.autocrlf=false`.
2. **Telemetry is on by default.** `bot.env` from the template has `TELEMETRY=true`, and `sdk/bug-report.ts` posts to `https://rs-sdk-demo.fly.dev/bug-report`. Our `createBot` rewrites it to `TELEMETRY=false`.
3. **Cheats are off locally.** `server/engine/src/server/login/LoginThread.ts:60` sets `staffmodlevel = 0`. Not patched. Practice presets use `sdk/test/utils/save-generator.ts` instead.
4. **The lite client mishandles locs on bridged tiles.** On a tile whose level-1 map flag has LinkBelow, `server/webclient/src/lite/protocol/zone.ts` keys a loc change by the player's level, but `lite/world/CollisionBuilder.ts` reads the raw level (one up) there, so an opened door stays shut in the routing map; and `lite/world/SceneLite.ts` answers `nearbyLocs` from the raw level under the bridge. The browser client handles both (`client/Client.ts` `locChangeUnchecked`, `World.setBridge`). Workaround: `packages/core/src/bridgefix.ts` `fixBridgedLocChanges(session.client)` wraps SceneLite at runtime (no vendor edit). Opt-in per script; used by `scripts/generated/quest-seaslug.ts` (fishing platform doors). Evidence:(`research/quest-plan.md` 1n).
5. **Install packet observers before the lite session pumps.** Local patch: `server/webclient/src/lite/session.ts` accepts an optional `onClient` callback after construction and before the first packet pump. It closes the connection if that callback throws. The two observer hunks are stored in [rs-sdk-session-observer.patch](rs-sdk-session-observer.patch), against the pinned file; other local vendor changes are excluded. `packages/core/src/inprocess.ts` installs its shim there, so the first full equipment packet cannot arrive before its observer. Account ownership is recorded after the session starts successfully. A missing full packet remains unknown; partial packets, a retained component or another client's inventory cannot establish readiness. The pin is unchanged. Packet-order tests and the native quest/smelting/supply evidence are retained under `.practice/travel-native-20261027/`.

6. **Working-tree vendor changes.** `patches/rs-sdk-working.patch` holds every local change under `vendor/rs-sdk` that the pin does not carry (pack config and interface tools, the lite session observer, `session-end.test.ts`). A fresh clone applies it with `git -C vendor/rs-sdk apply ../../patches/rs-sdk-working.patch`.
