# Phase 2: Script Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bots run in the same process as the game client. Actions check their own result in game ticks. A world graph routes across floors through stairs, ladders and doors, using rules mined from content. Reflexes eat and flee. Five basic scripts are proven 10/10 at 300 ms ticks.

**Architecture:** `packages/core` wraps vendored rs-sdk from the outside. (1) `inprocess.ts` feeds BotSDK from a LiteClient through a fake socket. (2) `ticks.ts` and `act.ts` give tick waits and checked actions on top of BotSDK state. (3) `world.ts` builds a portal graph: rs-sdk `findLongPath` for one-floor legs, plus `knowledge/transports.json` and `knowledge/doors.json` for edges with requirements. (4) `reflex.ts` runs tripwires on every state. Proven scripts in `scripts/proven/` use only these modules.

**Tech Stack:** TypeScript, Bun 1.3.14, `bun test`. rs-sdk at `b565f2d920bf6f5ec427bc6f66dc6fd64a2e15c1`.

**Spec:** `docs/superpowers/specs/2026-10-22-rs-sdk-bot-harness-design.md` (Phase 2, sections 7.1 and 7.5). **Recon:** `research/phase2-recon.md` (file:line facts used below).

## Global Constraints

- Do not edit `vendor/`. Import vendor modules by relative path.
- Demo settings for proving: `NODE_TICKRATE=300`, `NODE_XPRATE=25`.
- Time is measured in game ticks, never in fixed sleeps, except the login spacing of 1.5 s (swarm.ts:432).
- Every in-process session passes an explicit `cacheDir` under `.practice/cache`.
- One login per account. Never run `runner.ts` and an in-process session for the same bot.
- `TELEMETRY=false`, `SHOW_CHAT=false` (env enforced by `createBot`).
- Data comes only from `knowledge/*.json`, regenerated by `bun packages/knowledge/src/build.ts`.

## Review Focus

1. **The session dies mid-action** (`onEnd` reason other than `stopped`): pending actions must reject at once, not wait for the 60 s SDK timeout.
2. **An action the server silently refuses** (UNSET_MAP_FLAG, no message): a checked action returns `rejected` within its tick budget, not `timeout` after it.
3. **A route needs a door the bot cannot open** (quest, key, skill, one-way, wrong side): the router must not choose it, or must report `no_route`, never walk into it forever.
4. **A route leg ends one tile off** (`exact: false` transport edge): the walker re-reads position and continues.
5. **HP drops while a script is mid-loop with no food**: the reflex must flee and the script must see `aborted: 'reflex'`.

### Task 4: World graph router

**Files:**
- Create: `packages/core/src/world.ts`
- Test: `packages/core/test/world.test.ts`, `packages/core/test/world.data.test.ts`

**Interfaces:**
- Consumes: `knowledge/transports.json`, `knowledge/doors.json`, `findLongPath` from `vendor/rs-sdk/sdk/pathfinding.ts`
- Produces:
  - `type Tile = { x: number; z: number; level: number }`
  - `type Leg = { kind: 'walk'; to: Tile } | { kind: 'transport'; loc: string; option: string; at: Tile; to: Tile; exact: boolean }`
  - `interface Account { skills: Record<string, number>; varps: Record<string, number>; items: string[] }`
  - `createWorld(opts?: { pathLength?: (from: Tile, to: Tile) => number | null; blockedDoors?: (acct: Account) => Tile[] }): World`. `pathLength` defaults to `findLongPath` length, `null` when the last waypoint is not the goal.
  - `World.route(from: Tile, to: Tile, acct: Account): { ok: true; legs: Leg[]; cost: number } | { ok: false; reason: 'no_route' }`
  - The algorithm is Dijkstra over the portal nodes: start, goal, every transport `at` tile and every transport `to` tile. Same-level node pairs are linked when `pathLength` is not null. Transport edges cost 3 ticks. Doors the account cannot pass are given to `findLongPath` as `blockedDoors` (Review Focus 3).

- [ ] **Step 1:** Unit tests with an injected `pathLength`, on a tiny two-level world:
  - the route takes the stair edge when the goal is on level 1
  - it reports `no_route` when the only stair is behind a skill door the account fails
  - it picks the cheaper of two stairs
- [ ] **Step 2:** Run `bun test ./packages/core/test/world.test.ts`. Expected: FAIL.
- [ ] **Step 3:** Implement. Cache `pathLength` results per pair within one `route` call. Precompute nothing at import (the 27.5 MB collision JSON loads once, lazily).
- [ ] **Step 4:** Run the unit tests. Then run the real-data test: route from near the foot of the Varrock Museum stairs (`from (3259,3446,0)` per `transports.json`) to their top `(3259,3449,1)`, expect a `transport` leg with `loc: 'stairs'`. ### Task 5: Route walker and reflexes

**Files:**
- Create: `packages/core/src/walk.ts`, `packages/core/src/reflex.ts`
- Test: `packages/core/test/walk.test.ts`, `packages/core/test/reflex.test.ts`

**Interfaces:**
- Consumes: `Session`, `checked`, `World.route`, `Leg`
- Produces:
  - `walkRoute(s: Session, legs: Leg[], opts?: { maxRetriesPerLeg?: number }): Promise<Outcome>`. A walk leg uses `bot.walkTo`, checked with `atTile(…, tol 2)`. A transport leg uses `bot.interactLoc(loc, option)`, checked with `levelIs(to.level)` and a tile within 2 of `to` (exact) or 3 (not exact). After a non-exact leg it re-reads its position before the next leg (Review Focus 4).
  - `goTo(s: Session, world: World, to: Tile, acct: Account): Promise<Outcome>`
  - `startReflexes(s: Session, rules: { eatBelowHp: number; fleeBelowHp: number; foods: RegExp; safeTile: Tile }): { stop(): void; aborted: AbortSignal }`. On each tick: if HP is below `eatBelowHp` and food exists, eat. If HP is below `fleeBelowHp` and no food, abort the signal and walk to `safeTile` (Review Focus 5). `checked` returns `aborted` when the signal fires.
