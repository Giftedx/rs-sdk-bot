# Implementation Plan

[Overview]
Turn `rs-sdk-bot` from a multi-agent research workspace into a clean, owner-managed bot project: pin rs-sdk as a submodule, normalize line endings, keep generated outputs out of git, consolidate agent-era docs, prune merged branches, and connect a remote, without changing bot behavior.

Scope: repository layout, git hygiene, and vendoring. No gameplay logic, bot script, or planner math changes. Verified state at the time of planning: `master` at `2663711`; 483 tracked files; `phase0-1` and `phase2` are both fully merged into `master` (0 commits ahead); no git remote is configured; `vendor/rs-sdk` is at `b565f2d920bf6f5ec427bc6f66dc6fd64a2e15c1` and clean; `collection-plan.json` is untracked; 13 tracked files have mixed line endings and 82 are LF in the index but CRLF on disk. A bundle backup exists at `f:\dev-on-f\osrs-rs-research\_backup\rs-sdk-bot-all.bundle`.

Context: this is the owner's project built on rs-sdk (MaxBittker/rs-sdk, MIT). It is not a fork the owner intends to submit upstream by default. `docs/agent-brief.md` and `research/` were written for parallel agents. Some of their rules (commit trailers, per-agent file ownership, `research/INDEX.md` ownership) do not fit a single owner.

Approach: ordered phases, each independently verifiable. Each phase ends with a commit (or a no-commit verification), typecheck, and tests. No history rewriting: no `reset`, `amend`, or `rebase`. The earlier session had index-lock collisions and a reset that mislabeled commits; neither may be repeated. Files referenced from code comments are not moved in the first pass.

[Functions]

New functions: none in the first pass. Optional gitlink function in Phase 4:
- `checkGitlink(rootDir: string, path: string, expected: string): { ok: boolean; actual: string }` in `scripts/check-pin.ts`. Runs `git -C rootDir ls-tree HEAD <path>`, parses the sha from the `commit` entry, and compares it with `expected`. Returns `actual: ''` when there is no entry.
